About the project

From an EEG window to a hardware classifier

NeuroSomno-HDL studies how a small neural network can classify EEG windows associated with sleep apnea using fixed-point arithmetic. It includes a Python signal-processing and training pipeline, a Verilog inference core, and host-side software for integration with a Zynq processing system.

There are two models. The software CNN works on the full 2,816-value signal window. The smaller fully connected network uses 784 interpolated values and is the model implemented in hardware. They are trained separately; the FPGA does not run the CNN.

The current published measurements use synthetic EEG. They help compare model behavior and numerical representations, but do not establish accuracy on patient recordings.

Signal processing

Preparing the EEG input

Python prepares each EEG window before it reaches the FPGA. The accelerator receives a vector of 784 values and returns scores for normal and apnea.

01

Acquire & clean

Read C3 and C4 EEG channels, resample to 128 Hz, suppress 50 Hz interference and retain the 0.5–45 Hz band.

02

Window & normalize

Create 11-second windows at a one-second stride. Normalize each channel, combine 2,816 values, then interpolate to 784 inputs.

03

Learn & quantize

Train a software CNN and a separate compact FCN. Export the FCN weights with convergent rounding into signed Q3.13 arithmetic.

04

Stream & classify

Send a 784-word vector into the accelerator. Four dense layers produce two signed scores; the larger score selects the class.

Software CNN baseline: three convolution stages

The CNN takes the full 2,816-value window as one input sequence. Its three convolution stages have 3, 50 and 30 output channels, with kernel sizes of 100, 10 and 30. The first convolution has stride 2. Each stage includes max pooling; batch normalization is used at the input and after the last convolution stage.

Global-average pooling reduces the final feature maps to 30 values, followed by a linear layer with two outputs. This is a software baseline for comparison. The FCN above is the network exported to Verilog.

Training and export

The FCN used for training has the same four layers as the RTL: 30, 30, 10 and 2 neurons. All four layers are included in the fixed-point export.

Host interface

AXI-Stream carries the input vector. AXI-Lite provides control and class readout. A host processor manages the inference sequence.

Other blocks in the repository

The software CNN and standalone convolution, pooling and IIR blocks support exploration. They are not wired into the deployed FCN top.

How the split was made

Synthetic subject 3 is used for training, subject 2 for validation, and subject 1 for testing. Keeping subjects separate prevents overlapping windows from the same subject appearing in both training and testing. Class balancing is applied only to the training data.

What the errors mean

The FCN misses 6 of the 150 apnea-labeled test windows, while the CNN misses 14. Neither produces a false positive in this split. The floating-point FCN and integer reference make the same class decisions on all 590 windows.

Data movement

One inference transaction

The processor starts an inference, sends a complete vector, then reads the class after completion. This walkthrough follows those protocol stages; it does not simulate the neural network or measure elapsed clock cycles.

Two AXI interfaces, different jobs

AXI-Lite handles control, parameter writes and status reads. AXI-Stream carries the 784 input words. A word is accepted only when VALID and READY are both high; TLAST marks the last accepted word.

Input gaps are allowed. An early or missing TLAST aborts the frame. The host must use a timeout and reset before retrying an invalid transaction.

Fixed-point arithmetic

Representing values in Q3.13

Q3.13 represents each number with one sign bit, two integer bits and 13 fractional bits. The same signed integer operations are used by the reference model and the RTL.

Implementation notes

What is included, and what still needs a board

Repository guide

Neuron datapath, layer serializers, activation logic and the AXI-connected top level.

C driver and PYNQ host interface for programming parameters and starting inference.

MATLAB research pipeline; requires the relevant vendor toolboxes.
Is there a ready-to-program bitstream?

No. This repository provides the IP core and host software. A complete board design still needs the processing system, DMA, clock/reset wiring, interrupts, addresses and board constraints.

Does it process raw EEG entirely on the FPGA?

The active FCN core expects preprocessed vectors. The standalone convolution, pooling and IIR modules are separate research blocks. Offline zero-phase filtering and causal streaming filters are not interchangeable without validation or retraining.

Are the output scores probabilities?

No. The final layer is linear. Its two signed scores are compared directly; a tie selects normal. The sigmoid appears in the third layer, not at the output.

What does the episode counter represent?

The experimental telemetry treats each new classification as one second of contiguous observation. It counts an episode after ten consecutive positive epochs, once until a negative epoch. Arbitrary offline batches do not represent clinical event rates.

What measurements are still missing?

Patient-data generalization, routed timing closure, measured power, and physical DMA/interrupt behavior. Resource counts shown here come from synthesis of the core.
